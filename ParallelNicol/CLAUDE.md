# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this directory.

## 概要

**平行ニコル**でリタデーション R を測ったときに得られる

```
c = cos(2πR/λ)
```

について、

1. **単波長では次数（オーダー）m が決まらず、R が一意に定まらない**こと
2. **λ = 590 / 610 / 630 nm の 3 波長で測ると次数が確定する**仕組み

の 2 つを地続きで理解するための教育用 Web アプリ。主役は **2 の「なぜ 3 波長で決まるのか」**で、
1 はその前提として見せる。

「1 波長だと候補が 10 本 → 2 波長で 1 本に絞れるが誤差に弱い → 3 波長で確実になる」
という**候補が絞られていく過程**を、波長の ON/OFF と測定誤差の許容幅で体感させるのが狙い。

> **前提: 波長分散は無いものとする。**
> R は波長によらず一定（複屈折 Δn が波長に依らない）という理想化。これがあるので
> 「3 つの波長が同じ R を指す」という一致条件が使える。実材料では Δn に分散があり、
> R も波長依存になる（本アプリでは扱わない。UI にも注記を出す）。

姉妹アプリ `../Waveplate/`（実空間の波の伝搬）、`../PoincareSphere/`（ストークス空間）、
`../MOA/`（マイクロ波分子配向計）と同じ作り（ビルド工程なし・ダークテーマ・単一 `main.js`）。
ただし本アプリは **3D 表示を持たないため Three.js を使わず、Canvas 2D のみ**で描く
（＝姉妹アプリと違い CDN 依存がなく、オフラインでも動く）。

## 起動方法

```bash
node server.js          # デフォルト http://localhost:3000
PORT=8080 node server.js

```

## アーキテクチャ

- **`index.html`** — 左に操作パネル、右に表示エリア。Canvas は 4 つ:

  | id | 位置 | 内容 |
  |----|------|------|
  | `#phasor` | 左パネル下部（小） | 位相円。選択中の波長の δ = 2πR/λ の**巻き数 = 次数 m**。x 射影が c |
  | `#polar0/1/2` | ① 最上段（横 3 並び） | **極座標グラフ**。試料を回したときの透過率 T(θ)。45° の値が c |
  | `#curves` | ② | c–R 曲線を 3 波長分重ね描き。各々に測定値 c_i の水平線と交点マーカー |
  | `#combs` | ③ | **候補コム**。共通の R 軸に対し波長ごとに 1 段ずつ候補を縦チックで並べる。全段そろう R をハイライト |
  | `#match` | ④ | **一致度曲線** D(R) = max_i&nbsp;\|Δc_i\|。tol の水平線より下が「生き残る」領域。谷の深さで誤差余裕を見る |

  **極座標は必ず波長ごとに別カード**にする（`#polarRow` の 3 カラムグリッド）。
  1 枚に重ね書きすると 3 つの形の違い＝測定値の違いが読めなくなるため。

  パネル先頭の `.appnav` は姉妹アプリ（`../Waveplate/` / `../PoincareSphere/` / `../MOA/`）への
  切り替えリンク（公開サイト `_site/` 配下でのみ有効。単体で `server.js` を起動したときは 404）

- **`main.js`** — アプリ本体（ES Module、単一ファイル）
  - `state` に全パラメータを集約（`R`, `use[3]`, `tol`, `nicol`, `showT`, `focusLam`, `playing`, …）
  - `refresh()`: パラメータ変更時の一括更新
    （`measure` → `buildCandidates` → `scanMatches` → 各 `draw*` → `updateStatus`）
  - `measure()`: 真の R から測定値 `cMeas[i] = cos(2πR/LAMBDAS[i])` を作る
  - `tAzimuth(c, θ)`: 方位角 θ での透過率（極座標グラフの動径）
  - `drawPolarCard(canvas, i)`: 波長 i の極座標グラフ 1 枚
  - `buildCandidates()`: 波長ごとに `R = λ_i(m ± α_i/2π)` を列挙し
    `{ lam, m, branch: '+'|'−', R }` の配列を返す（`#combs` のチック）
  - `maxDev(R)`: **D(R) = max_i |cos(2πR/λ_i) − cMeas[i]|**（有効波長のみ）。
    「全波長で誤差が tol 以内」という判定条件そのものなので、判定・グラフ・代表点選びの
    すべてでこの 1 つの指標を使う（二乗和など別指標を混ぜない）
  - `scanMatches()`: `0..R_MAX` を `SCAN_STEP` 刻みで走査し、`D(R) ≤ tol` が続く区間ごとに
    **D が最小の点**を代表点として拾う。戻り値が「生き残った候補」＝
    `#combs` のハイライトと状態表示に使う
  - `drawPhasor()` / `drawCurves()` / `drawCombs()` / `drawMatch()`: 各 Canvas の描画
  - `render()`: `requestAnimationFrame` ループ。R の自動掃引・DPR/リサイズ処理
- **`server.js`** — Node.js 組み込み `http` のみの静的サーバ（姉妹アプリと同一）
- **`README.md`** — ユーザー向けの使い方（UI 変更時は忘れず更新すること）

## 物理仕様

### 測定モデル（平行ニコル）

- 偏光子 → 試料（複屈折体、リタデーション R [nm]、光学軸の方位角 θ）→ 検光子
- 位相差 δ = 2πR/λ、**c ≡ cos δ = cos(2πR/λ)**
- **方位角 θ を回したときの透過率**（`tAzimuth`。極座標グラフ ① の動径）:
  - **平行ニコル** T∥(θ) = 1 − sin²2θ · sin²(δ/2)
  - 直交ニコル T⊥(θ) = sin²2θ · sin²(δ/2)
  - `sin²(δ/2) = (1 − c)/2` なので **形は c だけで決まる**。90° 周期
- **測定は θ = 45°** で行う（複屈折の効きが最大になる向き）。そこでは
  - **平行ニコル** T∥ = cos²(δ/2) = **(1 + c)/2**
  - 直交ニコル T⊥ = sin²(δ/2) = (1 − c)/2
- したがって単波長の平行ニコル測定は、実質 **c を 1 つ測っているだけ**。
  極座標グラフはその 1 点がどこから来たのかを示すためにある
  （θ = 0° / 90° では複屈折が効かず T∥ = 1、45° で最も深くくびれる）

| R | δ | c | 平行ニコル | 直交ニコル |
|---|---|---|-----------|-----------|
| m·λ（整数次） | 2πm | +1 | 明（T=1） | 暗（T=0） |
| (m+1/2)·λ | (2m+1)π | −1 | 暗（T=0） | 明（T=1） |
| (m+1/4)·λ | — | 0 | T=1/2 | T=1/2 |

### 単波長での次数の不定性

測定した c から δ を逆算すると、主値 `α = arccos(c) ∈ [0, π]` に対し

```
δ = 2πm ± α        (m = 0, 1, 2, …)
R = λ · ( m ± α/(2π) )
```

- **周期 λ の縮退**: R を λ だけ増やしても c は変わらない ＝ **次数 m が決まらない**
- **± の折り返し縮退**: 同じ次数の中でも `λ(m + α/2π)` と `λ(m+1 − α/2π)` が同じ c を与える
- よって単波長で決まるのは **R mod λ をさらに λ/2 に畳んだ量**だけ
- `m = 0` の `−` ブランチ（R < 0）は物理的に無いので候補から除く

### 3 波長（590 / 610 / 630 nm）で次数が決まる仕組み ← 本アプリの主題

波長分散が無いので、**真の R は 3 つの候補列すべてに現れる唯一の値**。
逆に言えば、3 本のコムが同時にそろう R を探せば次数が確定する。

- 完全な縮退が戻る周期は 3 波長の最小公倍数 **LCM(590, 610, 630) = 2,267,370 nm ≈ 2.3 mm**。
  実用レンジ（〜数千 nm）では事実上一意
- **では何が限界か → 測定誤差**。厳密一致ではなく `D(R) ≤ tol` で判定するため、
  tol を大きくすると偽の候補が復活する。ここが「2 波長では足りず 3 波長にする」理由:

  | 使用波長 | tol = 0.05 | tol = 0.10 | tol = 0.15 |
  |----------|-----------|-----------|-----------|
  | 590 のみ | 10 候補 | 10 候補 | 10 候補 |
  | 590 + 610 | **1 候補**（1400） | 3 候補（799 / 1400 / 2001.6） | 3 候補 |
  | 590 + 610 + 630 | **1 候補** | **1 候補** | **1 候補** |

  （R_true = 1400 nm の場合。`scanMatches` と同じ判定で算出・検証済み）
- 一致度曲線 D(R) で見ると、真値以外で**最も浅い谷**は
  2 波長で **D = 0.084**（R ≈ 2001.6 nm）、3 波長で **D = 0.157**（R ≈ 2013.7 nm）。
  つまり **3 本目が許容できる測定誤差を約 2 倍（0.084 → 0.157）に広げる**。
  これが「3 波長にする」ことの定量的な意味であり、アプリで tol スライダーを
  0.05 → 0.10 → 0.15 と上げていくと、2 波長だけ先に破綻する形で体感できる

### 感度が悪くなる領域（アプリ内でも注意書きを出す）

- **c ≈ ±1 の近く**（明点・暗点の近傍）は cos の頂点で、R が動いても c がほとんど変わらないため分離が悪い
- **R が小さい領域**は 3 波長の位相差そのものが小さく、コムの間隔が詰まって区別しにくい
- **R ≈ 0 は常に手ごわい対抗馬**。R = 0 では全波長で c = 1 なので、
  測定値が c ≈ 1 のときは真値と R ≈ 0 付近が区別しにくい
- 実例: R_true = 610 nm（610 nm にとってちょうど整数次、c = 0.977 / 1.000 / 0.980）では、
  3 波長でも **R ≈ 14.4 nm** が候補として残り、tol = 0.02 まで絞っても消えない

## UI 操作項目

| 項目 | 範囲 | 既定 |
|------|------|------|
| 真のリタデーション R | 0–3000 nm（スライダー＋数値入力） | 1400 nm |
| 使用波長 | 590 / 610 / 630 nm の ON/OFF（チェックボックス） | すべて ON |
| 測定誤差の許容幅 tol | 0–0.15（スライダー、c の絶対誤差） | 0.05 |
| ニコル配置 | 平行 / 直交（ボタン。極座標 ① と曲線 ② の両方に効く） | 平行 |
| 表示 | c 曲線 / 透過率曲線 の切替、候補コムの次数ラベル ON/OFF | c, ON |
| アニメーション | R の自動掃引 再生/一時停止・速度 | 停止 |

- **入力は「真の R」**。アプリはそこから c_i を作り、「測定者には c_i しか見えない」体で
  候補を逆算して並べる。真値がその候補列の 1 本にすぎないこと → 3 波長でそれが 1 本に絞れること、
  という順で見せる
- 波長を 1 本だけ ON にすれば単波長の不定性、2 本で「ほぼ決まるが誤差に弱い」、
  3 本で「確実」という段階が同じ画面で比較できる。**この切り替えが本アプリの核**
- 表示する次数の上限は R の上限 3000 nm に合わせて波長ごとに `mMax = ceil(3000/λ)`

### 配色

590 / 610 / 630 nm は実際の色ではどれも橙〜赤で見分けがつかないため、
**波長の順序感（黄→橙→赤）は保ちつつ彩度・明度で分離した 3 色**を使う:

| λ | 色 | 用途 |
|---|-----|------|
| 590 nm | `#ffd166`（黄） | c 曲線・コム 1 段目 |
| 610 nm | `#ff8a5c`（橙） | c 曲線・コム 2 段目 |
| 630 nm | `#ff5c7a`（赤桃） | c 曲線・コム 3 段目 |
| 一致 | `#36d1c4`（シアン） | 3 段そろった R のハイライト・E(R) の谷 |
| 真値 | `#8ecbff`（水色） | 真の R の縦線（答え合わせ用） |

シアン＝「測定から決まった答え」、水色＝「実は真値」。既定では一致するので重なる。

## 特徴的な確認例

**既定（R = 1400 nm, 3 波長, tol = 0.05）**
測定値 c = **−0.698 / −0.280 / +0.174**（590 / 610 / 630 nm）。α/2π = 0.3729 / 0.2951 / 0.2222。

| λ | T∥(45°) | 候補 R [nm]（0–3000） |
|---|---------|----------------------|
| 590 | 0.151 | 220, 370, 810, 960, **1400**, 1550, 1990, 2140, 2580, 2730 |
| 610 | 0.360 | 180, 430, 790, 1040, **1400**, 1650, 2010, 2260, 2620, 2870 |
| 630 | 0.587 | 140, 490, 770, 1120, **1400**, 1750, 2030, 2380, 2660 |

3 段そろうのは **1400 のみ**。極座標グラフ ① では、590 が深くくびれた四つ葉、
630 はほぼ円に近い形になり、**3 波長で見え方がはっきり違う**ことが確認できる。

| 操作 | 結果 |
|------|------|
| 590 のみ ON | 候補 10 本。次数が決まらない（単波長の限界） |
| 590 + 610、tol = 0.10 | 799 / 1400 / 2001.6 の 3 本が生き残る（誤差に弱い） |
| 3 波長すべて、tol = 0.10（0.15 でも） | 1400 の 1 本。3 本目の効き目が見える |
| R = 610 に変更 | c = 0.977 / 1.000 / 0.980。3 波長・tol = 0.02 でも R ≈ 14.4 が残る（c ≈ 1 付近は感度が悪い例） |
| R = 1220（= 2λ @610） | 610 nm が整数次で c = 1 になりコムが疎に。R ≈ 28.7 が対抗馬として残る |
| R を 0→3000 へ掃引 | 3 本の c 曲線が異なる周期で振動。コムの一致点が R に追随して動く |

## 実装上の注意

- `scanMatches()` の走査刻み `SCAN_STEP` は 0.05–0.1 nm 程度。粗いと谷を取りこぼし、
  細かいと 60fps の掃引アニメーションで重くなる。**掃引中のみ刻みを粗くする**などの調整を検討
- 候補の代表点は「区間内で E 最小の点」を採る（区間の端を拾うと真値からずれて見える）
- `α = arccos(c)` は c が浮動小数で ±1 をわずかに超えることがあるので `clamp(c, −1, 1)` してから渡す
- LCM(590, 610, 630) = 2 · 3² · 5 · 7 · 59 · 61 = 2,267,370
